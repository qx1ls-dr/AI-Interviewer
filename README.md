# AI-интервьюер

Платформа динамических опросов студентов с AI-интервьюером. Заменяет обычные веб-анкеты (Google Forms и т.п.): вместо фиксированного списка вопросов языковая модель ведёт короткое интервью в чате и задаёт уточняющие вопросы. После закрытия опроса платформа удаляет из диалогов персональные данные, группирует проблемы и предложения по темам и показывает организатору дашборд с выводами и проверенными цитатами.

Учебный проект команды группы 4618 ГУАП, осенний семестр 2026/2027. Требования описаны в техническом задании (ТЗ).

## Как это работает

1. **Организатор** (преподаватель, деканат) вводит цели опроса. LLM готовит черновик плана интервью, организатор правит и публикует его. Студенты получают ссылку или QR-код.
2. **Респондент** даёт согласие на обработку ПДн и проходит интервью. Состояние интервью (тема, число уточнений) хранится в коде, а не только в контексте модели.
3. **Обезличивание**: регулярные выражения → Natasha NER и список запрещённых имён → LLM для косвенных идентификаторов. Исходные и обезличенные данные хранятся в разных БД.
4. **Анализ**: фасеты по каждому диалогу (JSON) → отнесение к темам кодбука → кластеризация остального → подсчёт уникальных респондентов SQL-запросами → порог анонимности k → отбор цитат с проверкой дословного вхождения.
5. **Дашборд**: охват, темы с долями и тональностью, карточки тем с цитатами, сильные стороны, блок «Как получены результаты». Выгрузка в PDF и XLSX.

## Сменная LLM

Весь код обращается к модели через один интерфейс `LLMProvider` ([backend/app/llm/base.py](backend/app/llm/base.py)). Модули:

| Модуль | Модель | Когда используется |
|---|---|---|
| `ClaudeProvider` | Claude API | основная модель |
| `GigaChatProvider` | GigaChat API | если передача в Claude недопустима |
| `YandexGPTProvider` | Yandex AI Studio | то же |
| `McpDevProvider` | Claude по подписке через MCP | только разработка и тесты на синтетических данных |
| `FakeProvider` | заглушка | автотесты |

Модель выбирается в `.env`, в том числе отдельно для каждой задачи (интервью, модерация, обезличивание, анализ, отчёт). **В Claude уходят только тексты, из которых уже удалены ПДн** (152-ФЗ). Ответы модели принимаются только в JSON по схеме и проверяются кодом. Числа на дашборде считает база данных, а не модель.

## Стек

- **Сервер:** Python 3.11+, FastAPI, Pydantic, SQLAlchemy, Alembic
- **Клиент:** TypeScript, React, Vite, Apache ECharts
- **Данные:** PostgreSQL 16 + pgvector (две БД: `identity` и `analytics`), Redis + RQ для фоновых задач
- **NLP:** Natasha, sentence-transformers (`multilingual-e5-large-instruct`), scikit-learn
- **Тесты и качество:** pytest, ruff, ESLint, GitHub Actions
- **Развёртывание:** Docker Compose

```

    api/          HTTP-эндпоинты

```

## Быстрый старт

Нужны Docker, [uv](https://docs.astral.sh/uv/) и Node.js 22.

```bash
cp .env.example .env            # заполните ключи API
docker compose up -d db redis   # PostgreSQL и Redis

cd backend
uv sync                         # зависимости сервера (+ --extra nlp для обезличивания и анализа)
uv run uvicorn app.main:app --reload
# проверка: http://localhost:8000/api/health, документация API: http://localhost:8000/docs

cd ../frontend
npm install
npm run dev                     # http://localhost:5173
```

Тесты и проверки:

```bash
cd backend && uv run pytest && uv run ruff check . && uv run ruff format --check .
cd frontend && npm run lint && npm run build
```

## Режим разработки с MCP

Чтобы не тратить платные токены Claude API, при разработке LLM-задачи может выполнять Claude по подписке разработчика через MCP (п. 4.5.3 ТЗ). Включается `DEV_MODE=true` и `LLM_DEFAULT_PROVIDER=mcp_dev`. В этом режиме обрабатываются **только синтетические и тестовые данные**, реальные ответы студентов по подписке не передаются. В эксплуатации `DEV_MODE=false`, и MCP-сервер не запускается. Сам сервер появится на этапе 2.4.

## Как вносить изменения

- Работаем в отдельных ветках и через pull request в `main`, прямые пуши в `main` не делаем.
- Перед PR прогоните тесты и линтеры (их же запускает CI).
- Ключи API только в `.env`. Реальные ответы студентов, выгрузки и дампы БД в репозиторий не кладём.
